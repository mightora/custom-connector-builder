Custom Connector Builder

Build Power Platform custom connectors without wrestling with YAML or C# from scratch. Define your connector step by step and get ready-to-use code.

Start building View examples

What This Tool Helps With

Custom connectors are powerful, but the configuration files can be daunting. This tool guides you through the process and generates everything you need.

  • 📄

    OpenAPI YAML

    Generates valid OpenAPI 2.0 (Swagger) YAML that you can import directly into Power Platform.

  • ⚙️

    C# Script Code

    Creates the C# policy template script to transform requests and responses inside the connector.

  • 🧱

    Visual Block Builder

    Assemble C# logic visually using pre-built blocks for common patterns like validation and calculations.

  • 🔒

    Authentication Patterns

    Supports no auth, API key, Basic Auth, and OAuth 2.0 – with the correct YAML generated automatically.

  • 🧮

    Calculation-Only Connectors

    Build connectors that perform calculations entirely inside the policy template – no external API needed.

  • 📋

    Ready-to-Use Examples

    Load working examples like the Dad Jokes connector and the VAT Calculation helper to get started quickly.

Step 1 – Choose connector type

Select the type of connector you want to build. This determines the overall pattern of the generated code.

Step 2 – Define connector name and description

Give your connector a clear, descriptive name. This appears in the Power Platform connector list.

Step 3 – Choose authentication pattern

Select how your connector authenticates with the API.

Step 4 – Add actions

Actions represent the individual API operations your connector exposes to Power Platform flows and apps.

    Step 5 – Configure inputs

    Add parameters to each action. Parameters define what information the caller must provide.

    Step 6 – Configure responses

    Define the response schema for each action. This tells Power Platform what data the connector returns.

    Step 7 – Add optional C# logic

    Add custom C# logic that runs inside the policy template. You can also use the Block Builder below. Leave empty to use the default pass-through template.
